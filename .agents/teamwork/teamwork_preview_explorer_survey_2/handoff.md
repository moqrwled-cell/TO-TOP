## 2. Logic Chain

1. **Native Linking Chain**:
   - `package.json` defines `@capacitor/local-notifications` and `@capacitor/geolocation`.
   - However, `android/app/capacitor.build.gradle` has empty `dependencies`, `android/capacitor.settings.gradle` lacks plugin projects, and `capacitor.plugins.json` is `[]`.
   - Therefore, the native Android build is out-of-sync with npm packages. Running on device or native build will fail to execute plugin native bridges until `npx cap sync` is run.

2. **Android OS Permissions Chain**:
   - `android/variables.gradle` targets SDK 36.
   - Android 13+ (API 33+) requires `POST_NOTIFICATIONS` in `AndroidManifest.xml` to display/schedule local notifications.
   - Android requires `ACCESS_FINE_LOCATION` and `ACCESS_COARSE_LOCATION` to access device location.
   - Android 12+ requires `SCHEDULE_EXACT_ALARM` or `USE_EXACT_ALARM` for alarms scheduled at precise moments.
   - `AndroidManifest.xml` only declares `INTERNET`.
   - Therefore, even if JavaScript calls native methods, Android OS will immediately reject or block notification display and location requests.

3. **Notification Scheduling Chain**:
   - Requirement R2 stipulates: *"The codebase contains explicit calls to `@capacitor/local-notifications` `schedule` method for both tasks and prayer times."*
   - Inspection proves there are 0 calls to `LocalNotifications.schedule` in the entire codebase.
   - Tasks in `OrganizerView` have zero notification triggers.
   - Routine and prayer notifications currently rely on component-scoped JavaScript `setInterval(..., 60000)` calling browser DOM `window.Notification`.
   - In mobile environments (Capacitor/Android), `setInterval` is killed or throttled when the screen is locked, the app is backgrounded, or the user switches tabs. Web `new Notification()` does not show native Android notifications.
   - Therefore, background/offline task reminders and prayer adhan alerts are completely non-functional on Android in the current state.

4. **Prayer Calculation Chain**:
   - `WorshipView` fetches from `https://api.aladhan.com/v1/timings`.
   - It requires active internet connection and active geolocation.
   - If either network is unavailable or GPS is denied, it halts and fails to render prayer times.
   - By adopting an offline mathematical prayer engine (such as the standard `adhan` library or astronomical formulas) combined with default coordinates (Makkah or city choice), prayer times and their scheduled local notifications can function reliably 100% offline.

## 4. Conclusion & Actionable Architecture Plan

The application currently has the necessary npm dependencies installed, but has **zero native scheduling implementation**, **no native Android manifest permissions**, and **no sync between npm and the Android project**.

To fulfill Requirements R2 and R3 and satisfy all acceptance criteria, the implementation team must execute the following structured tasks:

### 1. Android Manifest & Native Sync
- Update `android/app/src/main/AndroidManifest.xml` to include:
  ```xml
  <uses-permission android:name="android.permission.POST_NOTIFICATIONS" />
  <uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />
  <uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION" />
  <uses-permission android:name="android.permission.SCHEDULE_EXACT_ALARM" />
  <uses-permission android:name="android.permission.RECEIVE_BOOT_COMPLETED" />
  <uses-permission android:name="android.permission.WAKE_LOCK" />
  ```
- Run `npx cap sync android` to sync plugins into `capacitor.build.gradle` and `capacitor.settings.gradle`.

### 2. Centralized Notification Service (`src/services/notificationService.js`)
Create a robust service wrapping `@capacitor/local-notifications` with web fallback:
- **`requestNotificationPermission()`**: Requests native notification permissions with try/catch and logs/returns status.
- **`scheduleTaskNotification(task)`**: Parses task time, constructs a local notification ID, and calls:
  ```javascript
  await LocalNotifications.schedule({
    notifications: [{
      id: Math.abs(Number(task.id) % 2147483647),
      title: "تذكير بمهمة: " + task.text,
      body: "حان موعد إنجاز مهمتك المجدولة",
      schedule: { at: targetDate, allowWhileIdle: true },
      sound: 'beep.wav'
    }]
  });
  ```
- **`cancelTaskNotification(taskId)`**: Calls `LocalNotifications.cancel({ notifications: [{ id: ... }] })`.
- **`schedulePrayerNotifications(timings)`**: Schedules upcoming 5 daily prayers (Fajr, Dhuhr, Asr, Maghrib, Isha) at exact prayer time or 10 min prior via `LocalNotifications.schedule()`.

### 3. Dedicated Offline Prayer Service (`src/services/prayerService.js`)
- Install or embed the `adhan` library for 100% offline mathematical calculation of prayer times based on latitude, longitude, and calculation method (e.g., Umm Al-Qura, Egyptian General Authority, MWL).
- Add coordinates fallback: If `@capacitor/geolocation` permission is denied or location disabled, fallback gracefully to default coordinates (e.g. Makkah: `lat: 21.4225, lng: 39.8262`) or user-selected city in Settings, ensuring prayer times never crash or fail.
- When prayer times are obtained or recalculated, automatically schedule the upcoming local notifications.

### 4. Integration into Organizer & Settings
- In `src/features/organizer/OrganizerView.jsx`: When `addTask` is submitted with a time, call `notificationService.scheduleTaskNotification(newTask)`. When a task is deleted or toggled complete, cancel the scheduled notification.
- In `src/features/settings/SettingsView.jsx`: Add notification and location toggle/status indicators so users can verify permissions and trigger reschedules.
